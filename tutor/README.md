# Tutor — Claude Code Plugin

Audience-aware tutorial generation and Q&A for any codebase. Tutor writes project tutorials tailored to your configured audience and focus areas, and answers questions grounded in those tutorials.

## Installation

Add this plugin to your Claude Code environment:

```bash
/plugin add path/to/tutor
```

Or from a marketplace:

```bash
/plugin marketplace add <marketplace-repo>
/plugin install tutor@<marketplace-name>
```

## Skills

### `/tutor:init` — One-time setup

Run once per project to configure tutorial preferences:

```bash
/tutor:init
```

This will:
1. Infer project context from README, package metadata, etc.
2. Ask about your audience, focus areas, writing style, and trigger mode
3. Write `.tutor/config.yaml` (settings) and `.tutor/GUIDE.md` (writing instructions)
4. Optionally inject trigger instructions into CLAUDE.md
5. Create a `tutorials/` directory

### `/tutor:write` — Generate tutorials

Write a tutorial about any topic in your codebase:

```bash
# Write about a specific topic
/tutor:write the caching layer

# Write about your current work
/tutor:write

# Quick version (lighter focus, shorter)
/tutor:write --preset quick the auth module

# Comprehensive deep dive
/tutor:write --preset deep-dive state management

# One-off audience override
/tutor:write --audience beginner the API endpoints

# Update an existing tutorial after code changed
/tutor:write --update 01a-data-models
```

The writing flow:
1. Loads your config and writing guide
2. Researches relevant source files using subagents
3. Presents a section outline for your approval
4. Writes the full tutorial following your GUIDE.md

### `/tutor:ask` — Q&A grounded in tutorials

Ask questions answered from your existing tutorials first, source code second:

```bash
/tutor:ask why did we choose SQLite over Postgres?
/tutor:ask how does the compile cache work?
/tutor:ask what's the auth flow?
```

When tutorials don't cover a question, it answers from source code and offers to create a new tutorial to fill the gap.

## Configuration

### `.tutor/config.yaml`

Generated by `/tutor:init`. Human-editable. Controls:
- **audience**: Who reads tutorials, their technical level, assumed knowledge
- **focus**: Weight for each section type (skip/light/normal/heavy)
- **triggers**: When tutorials are written (manual/pre/post/both)
- **output**: Directory, style, naming convention, frontmatter
- **presets**: Named focus+length overrides (e.g., "quick", "deep-dive")

### `.tutor/GUIDE.md`

A tailored writing guide generated from your config. Contains:
- Audience adaptation rules
- Section weight expectations
- Style rules
- Frontmatter format
- Naming conventions
- Quality bar definition

## Trigger Modes

| Mode | Behavior |
|------|----------|
| `manual` | Only write tutorials when you call `/tutor:write` |
| `pre` | Tutorial before implementation (tutorial-first development) |
| `post` | Tutorial after implementation |
| `both` | Draft before, revise after |

Non-manual modes inject a snippet into your CLAUDE.md to prompt tutorial writing at the right time.

## How It Works

```
/tutor:init ──writes──▶ .tutor/config.yaml
                        .tutor/GUIDE.md
                        tutorials/
             ──injects─▶ CLAUDE.md (trigger snippet, if not manual)

/tutor:write ──reads──▶ .tutor/config.yaml + GUIDE.md
             ──reads──▶ source files, existing tutorials
             ──writes─▶ tutorials/{nn}-{slug}.md

/tutor:ask ──reads──▶ .tutor/config.yaml + GUIDE.md
           ──reads──▶ tutorials/*.md
           ──reads──▶ source files (if tutorials insufficient)
           ──offers─▶ /tutor:write (when gap detected)
```
